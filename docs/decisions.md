# Decisions

- D-1 (owner, 2026-11-03) Devices with special features (appliances, vacuums, intercoms, remotes) are brand independent: the user chooses the entities with an entity selector; the dashboard looks at the entity's domain, device class, unit, options and supported features. Nothing is hidden behind a brand name. A section with nothing bound or supported is not shown (a vacuum without a map has no map section; a custom picture can be given instead).
- D-2 (owner) A good-looking default layout for each such device that works with whatever is bound, using the dashboard's existing rows and components.
- D-3 (owner) When Hue Plus and scene engine are both installed, Hue lights are played by Hue Plus; scene engine plays every other light. A scene with both is played coherently on one clock. Scene engine holds nothing Hue-specific: it gets Hue's abilities from Hue Plus, like an expansion pack.
- D-4 (owner) Existing Hue Plus scenes that contain non-Hue lights keep working; new or edited mixed scenes belong to scene engine. Nothing is migrated automatically.
- D-5 (owner) Scene engine is updated for Home Assistant 2026.10 and published as a public repository next to the others.
- D-6 (owner) A device without an area in Home Assistant is placed by the user in a room; the choice is stored with the dashboard layout and Home Assistant's areas are not changed.
- D-7 (owner) The remote creator is a kind in the "Add device" list. The remote shows as a normal row and opens a popup with a grid of buttons. The grid has 3 columns by default; the number of columns is adjustable per remote and a button can take 2 columns. Each button has an entity and an icon (and an optional label).
- D-8 (owner) An image remote takes a picture by upload or by an existing `/local/` path. Touch areas are drawn over the picture. Nothing says "command sent": a message appears only when a command fails.
- D-9 (owner) A notification rule can watch any entity reaching a state; the battery rule also takes binary low-battery sensors.
- D-10 (owner) Push to talk is wanted for the intercom and for cameras that have a speaker (the guest room camera).
- D-11 (owner) Releases of home-control, hue-plus and scene-engine are published by the assistant when CI passes.
- D-12 (owner, 2026-11-07) Home Control is a scene engine for any light, and it is brand independent. Live scenes, areas, their storage, playing and the services that drive them live in Home Control's integration (the browser only shows and edits them), for every light. Supersedes D-3 and D-4 (Hue Plus no longer plays Hue lights, and scene engine is not a partner) and D-21 of Hue Plus ("Hue Plus owns live scenes, areas and effects"). Scene engine is removed when this is done: its repository is deleted on GitHub (owner's choice, 2026-11-07, after everything is verified; a git bundle of its history is kept in this folder).
- D-13 (owner, 2026-11-07) A "plus" integration (Hue Plus, a future Govee Plus) expands what Home Control can do for the lights of one brand. It is declared by a file `home_control.json` in its own folder and by services it provides: no Python import in either direction, so load order does not matter and a missing integration just disappears from the dashboard. The declaration names the lights it owns (by entity registry platform) and their command rate, the light effects it plays natively (id, label, group, icon), and a settings menu script (`menu.js`) that Home Control loads on the administrator's Settings page. Playing is a service of the plus integration. Without one, Home Control plays every light through `light.turn_on` and shows the effects the light and Home Assistant report. Decided in D-13: Hue Plus keeps everything that talks to the bridge itself (entertainment areas, Spotify sync, gradient zones, other bridge, Hue cloud, bridge scenes and their import, calibrated native effects and the bridge's command pacing). The Hue Plus menu in Settings and the effect catalogue move out of Home Control into Hue Plus (step B).
- D-14 (owner, 2026-11-07) Nothing the owner sees or does on the dashboard may change when this is done, with Hue Plus installed: same screens, same behaviour, same saved scenes and areas. Uninstalling a plus integration must not break scenes or areas: they keep working on the lights Home Assistant has left. So a saved area light keeps the light's entity registry `unique_id` next to its entity id, and an entity id that no longer exists is found again by that unique id (Hue Plus's entity and the Hue integration's own entity of a light share it).
- D-15 (owner, 2026-11-07) Light effects are data, not code in the dashboard. One catalogue syntax (`docs/effects-file.md`, JSON, schema 1) describes a brand's effects: their groups, labels, icons or preview colours, default brightness and speed, the calibration of the speed (which part of the light's own scale the slider covers) and colour variants. A plus integration ships its catalogue in `home_control.json` (Hue Plus: everything that was in the dashboard's Hue table) and a user can import a file in the same syntax, for any other brand, written by hand or with an AI's help; the dashboard validates it and says exactly what is wrong. A light's effects that no catalogue knows are listed as the light and Home Assistant report them. A file never carries code: the only picture it may carry is a palette or a named icon. A plus integration may also carry a picture (SVG) for an effect; it is checked against a short list of elements and attributes on both sides.
- D-16 (owner, 2026-11-07) A light that fades by itself is given its fade; one that cannot is given single commands at an update rate (1 to 60 per second, default 2, per scene) and this is marked experimental. A light the colour check let go of rejoins the scene when it shows the scene's colours again (a person's change is final: D-3).
- D-17 (owner, 2026-11-07) The Hue-specific parts of the dashboard are Hue Plus's, through the plugin API: Hue's scenes (rows, popup, light-panel tiles, import as a live scene), the Spotify sync and sync box, and the style choice of a gradient light. The dashboard keeps what is brand-independent: a *light made of zones* (the `zone_colors` and `entity_id` attributes) with its markers, its place in areas and live scenes, and a list for importing live scenes from any registered source. Without Hue Plus a scene of the Hue integration runs like any scene. The plugin API is only added to; a change to what exists increments `version`.
- D-18 (owner, 2026-11-07) In a live scene the zones of one strip (a light made of zones, found by the unique id of the light they are parts of) cover the palette between them in proportion to the scene's Range, whatever the strip's length, and stay centred on where the strip stands; the other lights are still placed by position. A look given to a strip is for the strip: an effect of its own that its plus integration can play makes the strip one light in the scene (its zones are not commanded), any other look goes to each zone. A light that was off when a scene started is not taken for one someone switched off until 10 seconds after its command was sent.
- D-19 (owner, 2026-11-07) In the live scene maker the colours come only from the Colors light, which the engine cycles and sends to the lights. The lights are not controlled from the maker except to include or leave out a light, give it its own brightness (the scene's brightness when no light is selected) and its own effect (with No effect first). No colour is shown for, or set on, a light, and colours are not joined to lights. A scene has a mode: linear (colours blend) or segmented (each colour as it is, no colour between); the other two Hue styles are not live scene modes. A gradient light's zones are played as separate lights next to each other (all five, which for a Hue light means its Segmented style while a scene plays, left as it is when the scene stops).
